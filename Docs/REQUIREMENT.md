## 1. 项目名称

**Agent-mini**

## 2. 项目描述

Agent-mini 是一个**最小可用 Agent**。

在**不依赖任何现有 Agent 框架**（langgraph、openhands、openclaw、PI 等）的前提下，从零实现一个 ReAct 范式的最小 Agent：它接收用户输入，自主判断应当直接回复还是调用工具，根据工具结果决定继续循环还是收敛输出；同时具备会话记忆、上下文管线拼接与**按轮次的滑动窗口压缩**、**HTTP 单一交互入口**、结构化可观测性与配置注入能力。

三点设计取舍：

1. **上下文仍做 token 计算**：每次调用 LLM 前统计实际 messages、tools Schema 和协议结构开销，与预算比较；超预算时裁剪或本地拒绝发送。不同 tokenizer 存在估算偏差，安全余量降低风险，但不保证服务端实际计数绝无超限；不做单条消息级裁剪。
2. **压缩按整轮丢弃**：超限时以「轮」为单位从最旧处整轮移除，绝不拆散一轮内部的消息；即"轮次窗口 + token 预算"**双触发**。
3. **只提供 HTTP 交互**：不实现 CLI、REPL、Web 前端等其它入口。

"最小可用"的判定标准（三条同时满足才算达标）：

1. 给定一条自然语言指令，Agent 能自主完成"判断 → 调工具 → 读结果 → 再判断 → 输出"的完整闭环；
2. 多轮会话中能正确引用前文，不丢失会话上下文；
3. 全部能力可在本地单机跑通，不需要任何 Agent 框架或托管 Agent 平台。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 可验证的判定 |
| --- | --- | --- |
| G-01 | 从零实现 ReAct 循环 | 单条指令可触发至少 1 次工具调用并基于结果收敛输出 |
| G-02 | 模型接入层可替换、可配置 | 仅改配置即可切换 base_url / model，不改代码 |
| G-03 | 六个内置工具可用且受沙箱约束 | calculator、search、todo、time、read_file、write_file 均可调用；越界访问被阻断 |
| G-04 | 具备短时与中期两级记忆 | Redis 承载当前会话窗口，MongoDB 承载可跨会话检索的历史 |
| G-05 | 上下文可控不超限 | 每轮计算 token 并与预算比较；超轮次窗口或超 token 预算时整轮丢弃最旧对话，保留最近 K 轮 |
| G-06 | HTTP 单一入口 | 仅通过 HTTP API 完成完整对话（含多轮），不提供 CLI 入口 |
| G-07 | 可观测、可治理 | 每次请求有 trace_id，异常有明确分类与错误码 |
| G-08 | 配置与依赖注入集中管理 | 模型、工具、Prompt 三类配置均由配置层统一提供 |

## 4. 模块分层与开发顺序

开发顺序**严格按下列序号推进**，一次只做一个模块的一个功能（见 `AGENT.md` §8）。

| 序号 | 模块分层 | 一句话职责 | 开发顺序说明 |
| --- | --- | --- | --- |
| 1 | 模型接入层 | 以 OpenAI Chat Completions 协议对接模型（实际使用 DeepSeek） | 一切能力的基础，最先打通 |
| 2 | Agent Runtime | ReAct 范式主循环：判断直答 / 调工具 / 读结果 / 再判断 | 消费模型接入层，是 Agent 的心脏 |
| 3 | Tool 能力层 | calculator、search、todo、time、read_file、write_file；沙箱；注册机制 | 为 Runtime 提供可调用能力 |
| 4 | Memory 记忆 | Redis 短时记忆 + MongoDB 中期记忆 | 让 Agent 跨轮次保持一致 |
| 5 | Context 管线、压缩策略 | 拼接上下文并计算 token 预算；按轮次滑动窗口压缩 | 在记忆之上解决"装不下"的问题 |
| 6 | 交互接口层 | HTTP 单一入口 | 让能力对外可用 |
| 7 | 可观测与治理 | 日志追踪、异常处理 | 让系统可诊断、可治理 |
| 8 | 配置与依赖注入 | 模型配置、工具配置、Prompt 配置 | 最后收口，把散落配置集中化 |

> **重要说明**：上述是**交付顺序**，不等于**依赖顺序**。逻辑上 Runtime 依赖模型层、工具层、记忆层、上下文层；配置层虽最后交付，但其能力以"先环境变量、后统一收口"的方式分两步落地，详见 `Docs/DESIGN.md` §7 决策 ADR-004。

> **支撑组件（不属于八层）**：系统数据库 **MySQL** 存放**系统模型、工具、会话管理**等信息，以及工具调用审计与请求指标，与 Redis（短时消息窗口）、MongoDB（对话正文）职责隔离、互不影响。它不占用上述八层的开发顺序，作为基础设施贯穿全程，设计见 `Docs/DESIGN.md` §3.9。

## 5. 每层职责与边界

### 5.1 模型接入层（LLM）

- **职责**：封装 OpenAI Chat Completions 兼容调用；透传 `tools` 定义；归一化响应（文本 / tool_calls）；处理超时、重试、错误分类；统计 token 用量。
- **边界**：**不**做提示词工程、**不**做上下文拼接与裁剪（属 Context 层）、**不**做工具调度（属 Runtime）、**不**保存任何会话状态。
- **输入**：`messages[]`、`tools[]`、模型参数（`temperature`、`max_tokens` 等）。
- **输出**：`LLMResponse`，含 `content`、可选 `reasoning_content`、`tool_calls[]`、`usage`、`finish_reason`；推理字段与最终文本分别解析，默认非思考模式，契约见 DESIGN §3.1。

### 5.2 Agent Runtime

- **职责**：实现 ReAct 基本循环——接收用户输入 → 判断直接回复或调用工具 → 调用工具 → 依结果判断继续循环或返回结果；维护消息历史顺序；执行安全阀（最大步数、总超时、重复调用检测）。
- **边界**：**不**直接发 HTTP 请求（经由 LLM 层）、**不**实现具体工具逻辑（经由 Tool 层）、**不**决定上下文长度（经由 Context 层）。
- **输入**：用户消息 + 会话 ID。
- **输出**：`AgentResult`，含最终回复、步数、工具调用轨迹、token 用量。

### 5.3 Tool 能力层

- **职责**：提供 calculator、search、todo、time、read_file、write_file 六个工具；提供统一的注册机制（名称、描述、参数 Schema、执行函数）；提供文件沙箱。
- **边界**：**不**决定何时调用工具（属 Runtime）、**不**访问会话记忆、**不**做重试与降级编排。
- **输入**：工具名 + 参数 JSON。
- **输出**：`ToolResult`，含 `ok`、`content`、`error_code`；工具内部异常必须转为结构化错误而非抛出。

### 5.4 Memory 记忆

- **职责**：短时记忆（Redis）保存当前会话消息窗口并可恢复；中期记忆（MongoDB）持久化历史消息并支持按时间倒序与关键词检索；实现过期与清理。
- **边界**：**不**做轮次统计与窗口裁剪（属 Context 层）、**不**做语义检索、**不**感知工具语义。
- **输入**：会话 ID、消息、检索条件。
- **输出**：消息列表、检索结果集。

### 5.5 Context 管线与压缩策略

- **职责**：拼接 system prompt、记忆片段、最多 K 个已完成历史轮次和当前轮；工具定义在请求顶层 tools 独立发送。统一统计 messages、完整 tools Schema 和协议开销，每次出站前复核预算；默认保留最多 10 个历史轮次，超轮次或 token 预算时整轮丢弃最旧历史。不可裁剪部分仍超预算则本地拒绝，不发送 LLM 请求。
- **边界**：**不**拆分或截断单条消息（不做 token 级细裁剪）、**不**做摘要生成（不调用模型）、**不**持久化记忆（写回由 Memory 层负责）。
- **输入**：会话 ID、当前用户消息、窗口轮次配置、token 预算（模型上下文上限 − 输出预留 − 安全余量）。
- **输出**：`ContextPayload`，含最终 `messages[]`、实际轮次、估算 token 数、裁剪触发原因（`rounds` / `tokens` / `both`）、被丢弃的轮次数。

### 5.6 交互接口层

- **职责**：**仅提供 HTTP API**（`POST /chat`、健康检查）；会话 ID 生成与透传；请求校验；错误码映射；返回结构化元数据。
- **边界**：**不**包含业务推理、**不**直接访问工具或模型、**不**提供 CLI / REPL / 图形界面。
- **输入**：HTTP JSON 请求（用户输入、可选会话 ID）。
- **输出**：HTTP JSON 响应（回复文本、trace_id、步数、用量）。

### 5.7 可观测与治理

- **职责**：结构化日志（JSON）；trace_id 贯穿请求-步骤-工具调用；异常分类体系与统一错误响应；耗时与 token 指标输出。
- **边界**：**不**接入外部 APM、**不**做告警与长期存储（非目标）。
- **输入**：各层的日志事件与异常。
- **输出**：结构化日志行、指标字段、标准化错误对象。

### 5.8 配置与依赖注入

- **职责**：加载并校验模型配置、工具配置（启停与参数）、Prompt 配置（system prompt 外置）；提供依赖注入容器完成对象装配；密钥仅从环境变量读取。
- **边界**：**不**承载业务逻辑、**不**做热更新（首版重启生效）。
- **输入**：配置文件 + 环境变量。
- **输出**：类型化配置对象、已装配的依赖图。

## 6. 核心用户场景

| 编号 | 场景 | 前置条件 | 主流程 | 异常路径 | 验收要点 |
| --- | --- | --- | --- | --- | --- |
| UC-01 | 直接问答 | 模型可用，无需工具 | 用户提问 → Agent 判断无需工具 → 直接回复 | 模型不可用 → 明确错误码 | 不产生工具调用，1 步收敛 |
| UC-02 | 计算器求值 | calculator 已注册 | 用户给算式 → 调用 calculator → 返回结果 | 危险表达式 → 拒绝并说明 | 结果准确，危险表达式被拒 |
| UC-03 | 时间查询 | time 已注册 | 询问当前时间 → 调用 time → 按时区返回 | 非法时区 → 参数错误 | 返回 ISO8601 且时区正确 |
| UC-04 | 待办管理 | todo 已注册 | 新增/查看/完成待办 | 空列表查询 → 返回空集合而非报错 | 同一会话内状态一致 |
| UC-05 | 读取文件 | 目标文件在沙箱内 | 指定路径 → read_file → 返回内容 | 路径越界 → 阻断并给出原因 | 沙箱外路径一律拒绝 |
| UC-06 | 写入文件 | 目标路径在沙箱内 | 指定路径与内容 → write_file | 超限或越界 → 拒绝且不落盘 | 写入后内容可被 read_file 读回 |
| UC-07 | 联网搜索 | 已配置搜索 provider | 提问 → 调用 search → 基于结果回答 | 未配置 provider → 明确提示未启用 | 未配置时不得伪造结果 |
| UC-08 | 多轮记忆 | Redis 可用 | 第 1 轮告知信息，第 2 轮引用 | Redis 不可用 → 降级为单轮并告警 | 第 2 轮能正确引用第 1 轮 |
| UC-09 | 上下文超限裁剪 | 历史轮次 > K 或完整请求估算 token > 预算 | 整轮丢弃最旧历史 → 重新计数 → 正常回答 | 不可裁剪部分仍超限 → CONTEXT_TOO_LARGE/400，不再请求 LLM | 保留系统提示、实际 tools、当前完整轮次及最多 K 轮历史 |
| UC-10 | 工具失败收敛 | 工具返回错误 | 工具报错 → Runtime 读取错误 → 决定重试或直接说明 | 连续失败 → 达上限后给出结论 | 进程不崩溃，用户得到可读说明 |
| UC-11 | 通过 HTTP 使用 | 服务已启动 | 调用 `POST /chat` → 得到回复与元数据 | 服务不可用 / 入参非法 → 明确错误码 | 单入口即可完成单轮与多轮 |
| UC-12 | 双窗口独立恢复 | 同一用户有 session A/B，todo 按 session 存储 | A 查天气并记待办 → B 写周报并记待办 → 交替携原 ID 继续追问 | 省略 ID → 生成新 session，不按用户身份合并 | 对话、工具状态和历史召回均不串扰 |
| UC-13 | 带工具追问 | 同一 session 已调用 calculator 或 todo | “算 2+2”→“再乘 3”，或新增待办后“完成刚才那条” | 工具参数错误 → 模型收到结构化错误再修正 | 第 2 轮正确引用前文且再次自主选择工具 |
